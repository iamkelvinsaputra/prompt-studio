# Prompt Studio v2.1.0

This is one release extending the existing V2 application. No V1.1/V1.2 releases or tags were created. No backend or V2.2 redesign is included.

## 1. Architecture changes

The typed character system, compiler, library, randomization, serialization, editor, provider-neutral generation state and Compose UI remain shared. Existing native HTTP implementations moved intact into a source set shared by Android, Desktop and Apple. History adds a small store interface, serialized state holder and shared list/detail UI. There are still three Gradle modules; the Apple launcher is an Xcode project, not another Gradle module.

## 2. Apple targets

`iosArm64` and `iosSimulatorArm64` produce the static `PromptStudio` framework. `iosApp/PromptStudio.xcodeproj` embeds it through Gradle's Xcode integration. The thin UIKit app/scene delegates present the shared Compose controller. Minimum iOS is 16; Apple Silicon simulator development is supported. Physical device installation requires normal Xcode signing/team configuration. Intel simulator is not configured.

## 3. Web target

`wasmJs` uses the existing Compose toolchain's browser executable and `ComposeViewport`. Production assets are in `shared/build/dist/wasmJs/productionExecutable`. The browser needs modern Kotlin/Wasm-compatible WebAssembly support. Authoring operates locally once assets load; there is no service worker or guaranteed cold-start offline installation.

## 4. Source sets

- `commonMain`: domain/compiler/editor, generation models and orchestration, history model/controller/UI, small platform contracts.
- `nativeGenerationMain`: shared native Ktor client and both provider implementations; Android/JVM/iOS depend on it.
- `jvmStorageMain`: file history implementation reused on Android and Desktop.
- `androidMain`: existing documents, Keystore, bitmap and OkHttp boundaries, Android history location.
- `jvmMain`: existing desktop file dialogs, session keys and CIO, Desktop history location and Skia thumbnails.
- `iosMain`: Darwin engine, app support storage, document/share UI, session credentials and Skia images.
- `wasmJsMain`: browser local storage, upload/download, IndexedDB and disabled native generation backend.
- `commonTest`: shared domain and generation/history tests. `nativeGenerationTest` shares provider mock tests across native targets. JVM, Apple and Wasm tests exercise their real storage boundaries.

## 5. Capabilities

`PlatformCapabilities` exposes `canGenerateWithByok` and `canSaveImage`; `GenerationBackend` supplies supported provider implementations. Web supplies no providers and false BYOK capability. This hides credential controls and disables unsupported historical regeneration without scattered platform-name checks. File import/export is implemented everywhere and needs no additional flags.

## 6. Adaptive Apple UI

The existing width-based Compose layout progressively reveals component navigation at 820 dp, library at 1080 dp and side preview at 1200 dp. Narrow phones use one editor with shallow selectors. The header wraps, long names truncate, and variation locks can collapse. Safe drawing and keyboard insets are applied after consumed scaffold insets. iPad portrait and landscape were exercised; split-view resizing uses the same width logic but was not separately smoke-tested.

## 7. Apple persistence and files

Character library JSON lives in Application Support/Prompt Studio/current-project.json. Existing shared serialization/migration stays unchanged. Foundation atomic writes provide file persistence. JSON import uses a document picker with security-scoped access and the shared size/schema validation. Export uses a temporary JSON file and a share sheet, including an iPad popover anchor. Image export uses the same share mechanism and original MIME/bytes; Photos permission is unnecessary. Temporary export files are cleaned after share completion.

## 8. Apple credentials

Apple keys are explicitly session-only and forgotten on app termination, as the UI states. Keychain was investigated; a persistent Keychain bridge was not added in this version. There is no custom encryption, UserDefaults key storage or credential serialization. Android retains its existing optional Keystore storage; Desktop retains session-only keys. This is personal BYOK software, not a recommended public-client production secret architecture.

## 9. Web persistence

Small library JSON uses `localStorage` under `prompt-studio-library-v1`; browser storage failures reach the editor's existing error handling. JSON upload/download uses the same native-compatible project schema. Upload rejects files over 1 MB before reading. Clipboard uses Compose's browser payload and reports failure, including a five-second limit for indefinitely pending permission requests. Clipboard requires a secure context (localhost or HTTPS) and browser permission.

## 10. Why Web generation is disabled

OpenAI/Gemini provider implementations and Ktor dependencies are excluded from the Web source-set graph. Web has no API-key input, its credential store refuses writes, and it displays the intentional native-app BYOK limitation. No provider secret is built into the client. Future server-backed generation can implement the backend boundary, but no server was added.

## 11. History domain

`GenerationRecord` has a UUID, epoch-millisecond creation time, version 1, MIME type, image reference and the existing `GenerationMetadata`. Metadata captures character ID/name/configuration, compiled prompt, provider/model, requested and effective output, quality/settings and provider request ID when available. Records sort newest-first with an ID tie-breaker and filter by current character. File references are constrained to the record ID.

## 12. Native history storage

Each record has `<id>.json` metadata and `<id>.image` original bytes in a private history folder. MIME metadata determines export extension; no transcoding occurs. Independent records isolate corruption without a single fragile index. Desktop uses Application Support/Prompt Studio/history; Android uses noBackupFilesDir/history; Apple uses Application Support/Prompt Studio/history. Native file operations run on Dispatchers.IO under a mutex. Save writes the image first, atomically writes metadata, and cleans the new image on metadata failure. Duplicate IDs cannot overwrite existing metadata or artifacts.

## 13. Web history storage

IndexedDB `prompt-studio-history`, database version 1, has metadata and images object stores. Save and delete use a transaction across both stores. Images are Uint8Array binary, never Base64 in localStorage; Base64 is only a temporary Kotlin/JS transfer representation. Quota/transaction failures are reported and no old records are evicted. With generation intentionally disabled, normal Web sessions do not create provider history yet; storage tests use explicit fixtures.

## 14. Snapshot and restore

Generate captures a detached serialized project and compiled prompt before network work starts. Only a successful result saves that exact metadata once. Editing during a request cannot change its record. Restore asks for confirmation and replaces structured design fields in the currently selected character while preserving its current ID/name, then persists normally. With unchanged compiler/schema this reproduces the historical prompt.

## 15. Generate Again

Uses the historical project, exact compiled prompt and provider/model/settings, not editor state. Provider request IDs are not reused. Unsupported catalog models/output combinations are rejected with an explanation and never silently substituted. Web hides this unsupported action. Normal native credential requirements still apply.

## 16. Character deletion

Character deletion does not touch history. Snapshot names/configuration remain readable under All Generations, and restore targets the current character. New character IDs now use UUIDs so a deleted identity cannot accidentally be reused and match old records.

## 17. Corruption, consistency and memory

Invalid metadata entries are skipped and counted while valid entries remain accessible. Missing/undecodable images show an unavailable state without discarding metadata. Delete requires confirmation and removes both artifacts and metadata; native deletion removes the artifact first so a failure remains retryable. Controller/store mutexes serialize save, refresh, load and delete. Provider success is shown before history persistence; persistence failure has a distinct warning and manual image export remains available. Successful save is protected from ordinary request cancellation. There is no automatic expiry or count limit.

The history list is lazy and retains small thumbnails only for composed rows. Android samples decoding; Skia targets scale into a 144-pixel raster and release intermediate native resources. Individual compressed images are read on demand; no list-wide full-image cache is created. Full detail and latest result can still retain their selected image. Metadata listing is linear in history size; pagination and thumbnail disk caching are not implemented.

## 18. Tests added

Common history tests cover snapshot/prompt serialization, chronological sorting/filtering, identity-preserving restore/compiler equivalence, character deletion/ID uniqueness, missing images, delete contract, success exactly once, no save on failure/cancel, storage failure preserving provider success, historical Generate Again, unsupported models, and invalid history envelopes. JVM file tests cover restart/corruption/missing images/deletion and duplicate/preflight failure preservation. Apple storage tests use real Foundation files. Wasm tests use real IndexedDB and transactional duplicate rollback. A Desktop Compose UI test uses a fake provider and real temporary history store to exercise detail, restore confirmation, Generate Again and confirmed deletion. Existing native provider request/response tests remain mocked and unchanged.

The first full build exhausted the old 3 GB Gradle heap during Apple release optimization. Gradle heap is now 8 GB; the subsequent full build passed (243 tasks). Final full build passed in 4m 8s: 243 tasks (72 executed, 171 up-to-date). Final Xcode launcher build also passed and the updated app was reinstalled and launched on iPhone. Final XML results: JVM 83 tests, Android host 77, iOS simulator 77, Wasm/ChromeHeadless 69; zero failures, errors or skips in each suite. `git diff --check` passed. Source and production Web assets had no provider-key-pattern matches; credential fields are absent from project/history serialization, and no real keys were entered during testing. This scan supplements the source-set and storage-boundary review; it is not a claim of formal security auditing. Webpack reports asset-size performance warnings for Compose/Skia Wasm; these are not test failures. No tests call real provider endpoints.

- iPhone 17 Pro simulator: launched shared editor, live preview and Copy; simulator clipboard contained the compiled prompt.

## 21. Live providers

Neither OpenAI nor Gemini was tested live on any platform: no live credentials were supplied. Both providers were exercised through Ktor mocks on native test targets. Apple Darwin wiring compiled; live Apple networking and real generated-image share sheets remain unverified. Web performs no provider generation, mocked or live; its history storage fixture is not presented as generated artwork.

## 22. Known limitations

Apple/Desktop credentials are session-only. No physical Apple device/signing validation was performed. Browser data remains origin-local and subject to user clearing/site quotas. Cold offline launch is not guaranteed without a service worker. History is device-local and excluded from character JSON; project transfer does not transfer artwork. There is no bulk clear/archive/sync. Native separate-file writes are ordered/atomic per file, not a crash-proof multi-file database transaction; abrupt process death between writes can leave an unindexed image. No silent cleanup deletes user artifacts. Very large metadata collections still require a full metadata scan. Apple import checks its size after Foundation reads the selected document, so a maliciously huge file can temporarily allocate more than 1 MB. Save-image UI is implemented on all relevant platforms, but actual provider image export was not tested live.

## 23. JVM assumptions

The main incompatible common dependency was native provider HTTP implementation/dependencies in commonMain. Only that implementation moved to nativeGenerationMain. No compiler/domain rewrite or platform-specific prompt wording was needed. Image decoding and clipboard payload construction remain explicit platform boundaries. The source-set name nativeGenerationMain includes JVM/Android and means native app capability, not Kotlin/Native exclusively.
